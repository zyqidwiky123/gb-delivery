# Workflow 1.4 — Perbaiki Storage Security Rules

**Severity:** 🔴 KRITIS
**Estimasi:** 0,5 hari
**Dependensi:** —

---

## Latar Belakang

Rules saat ini:

```
allow write: if request.auth != null;
```

Artinya **SEMUA user yang login** bisa nulis file di **manapun** di storage. Risiko:

- User bisa upload file sembarangan
- Bisa timpa foto merchant/driver milik orang lain
- Bisa upload file berbahaya

---

## Langkah

### 1. Edit storage.rules

Ganti isi `storage.rules` menjadi:

```javascript
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {

    // Helper — cek admin
    function isAdmin() {
      return firestore.exists(
        /databases/(default)/documents/users/$(request.auth.uid)
      ) && firestore.get(
        /databases/(default)/documents/users/$(request.auth.uid)
      ).data.role == 'admin';
    }

    // ===== MERCHANT PHOTOS =====
    match /merchants/{merchantId}/{allPaths=**} {
      allow read: if true;
      allow write: if isAdmin();
    }

    // ===== DRIVER PHOTOS =====
    match /drivers/{driverId}/{allPaths=**} {
      allow read: if true;
      allow write: if request.auth.uid == driverId || isAdmin();
    }

    // ===== QRIS IMAGES =====
    match /qris/{driverId}/{allPaths=**} {
      allow read: if true;
      allow write: if request.auth.uid == driverId || isAdmin();
    }

    // ===== MENU PHOTOS =====
    match /merchant_menus/{allPaths=**} {
      allow read: if true;
      allow write: if isAdmin();
    }

    // ===== FALLBACK (tidak ada akses) =====
    match /{allPaths=**} {
      allow read, write: if false;
    }
  }
}
```

### 2. Deploy

```bash
firebase deploy --only storage
```

### 3. Test

Coba upload dari aplikasi web sebagai user biasa — harus ditolak.

### Verifikasi

- [ ] `storage.rules` sudah diupdate
- [ ] Deploy sukses
- [ ] Admin bisa upload ke merchant/, merchant_menus/
- [ ] Driver bisa upload ke drivers/{uid}/, qris/{uid}/
- [ ] User biasa tidak bisa upload sembarangan
